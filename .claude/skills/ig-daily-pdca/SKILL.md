# 日次PDCA（PDCA の C の速報）
1. data/insights/ の最新を読む（`git fetch origin main` は GitHub アクセス1回。普段1日3回・最大4回、5回はしない。超えるなら「今日は読めず」）。今日の行が無ければ昨日までで書き、そう明記。
2. 「大元の配信先」の「Instagram日次結果」の今日の行に数字：プロフィールアクセス（H）・外部リンクタップ（I）・フォロワー数（K）・閲覧数（M）・ストーリー閲覧 朝1本目（N）・昼1本目（O）・保存数（R）。取れない数字は空欄。
3. 一番落ちている段（閲覧→リーチ→プロフィールアクセス→リンクタップ→申込）を1つ（V列）と、明日の改善1つ（W列）。週目標（「Instagram週次結果」V・W列）に対する今週の進み具合も見る。`改善:K-00X` の投稿は分けて見る。申込は「参加申込（自動）」。
4. 大きな改善案は日曜に回す（加藤さんの声かけは除く）。報告は2〜3行（今週の進み具合を含める）。夜中に push はしない。
