# 日次PDCA（PDCA の C の速報）
1. **GitHub には触らない**（11/11 加藤さん：GitHub は1日2回＝朝8:00の回と夜の制作の回だけ）。数字は、その日の朝8:00の回で読み込んだ data/insights/ を使う（そう明記）。今日の行が無ければ昨日までで書き、そう明記。
2. 「大元の配信先」の「Instagram日次結果」の今日の行に数字：プロフィールアクセス（H）・外部リンクタップ（I）・フォロワー数（K）・閲覧数（M）・ストーリー閲覧 朝1本目（N）・昼1本目（O）・保存数（R）。取れない数字は空欄。
3. 一番落ちている段（閲覧→リーチ→プロフィールアクセス→リンクタップ→申込）を1つ（V列）と、明日の改善1つ（W列）。週目標（「Instagram週次結果」V・W列）に対する今週の進み具合も見る。`改善:K-00X` の投稿は分けて見る。シグナル（保存数・リールの平均視聴時間・ホーム率 home_rate）も見て、改善は PDCA.md の「落ちている数字 → 試す改善」から1つ選ぶ。申込は「参加申込（自動）」。
4. ai_employees/PIPELINE.md「C. 毎日の管理」：32 投稿保守（予定と実績の突き合わせ・原因・出し直し）→ 29 管理数値（報告の先頭に「予定◯／投稿◯／失敗◯／Merge待ち◯／社長タスク残り◯／週目標◯%」）→ 「大元の配信先」の「社長タスク」タブを更新（✓ の行は消す、新しく要る作業は足す。優先・タスク・期限・所要・場所・メモ）。夜のストーリーの中身は気にしない（11/9）。
4.5 毎日の見回り（PIPELINE.md「C. 毎日の管理」5）：品質管理部と30 監督が、明日出る下書きを全部見る（--check・`tools/quality_check.py --since 明日`で100点・イベント状況との照合・NG表現・顔。ai_employees/QUALITY.md）。直したコミットは夜中に push せず、翌朝8:00の push に乗せる。
4.7 LINE（ai_employees/LINE_FUNNEL.md）：data/insights/line_daily.csv があれば「LINE +◯人（リンクタップ◯・登録率◯%）」を報告の1行目に。無ければ「LINE 不明（鍵待ち）」。
4.8 成長（ai_employees/GROWTH.md の1〜1.6）：その日に動いた社員ごとに「学びログ」タブへ学び1行（根拠つき・+5 EXP）。⭐・LV は E列の EXP から自動（tools/levels.py と同じ式）。⭐が上がった社員は報告に「⭐昇格」と書く。会社のLV（GROWTH.md の1）を判定して報告の1行目に書き、社員の EXP を「AI社員のレベル」タブの E列に足す。7日前の投稿の結果で勝ち・負けを判定し PATTERNS.md に1行。翌日の曜日テーマ（GROWTH.md の2）を1つ深掘りし、報告に1行。
4.9 **毎日の実験枠（10:00・19:00）**（11/13 加藤さん「日々良くなっていくように」）：8:00・12:00 は変えずに「比べる基準」にし、**10:00・19:00 の3本セットを実験枠**にする。
   - 今日の数字（ストーリーの閲覧・①→③の残り・リンクタップ・プロフィールアクセス）で、昨日の実験が基準（8:00・12:00）より良かったか悪かったかを1行で判定（数字が取れなければ「不明」）。良かった変更は残し、悪かった変更は戻す。
   - 明日の 10:00・19:00 に**変えるのは1つだけ**（例：①の見出し・②の動画の文・③のQRの見出し・背景・色）。studio/make_week3.py（翌週は make_week4.py）の明日の行を書き換え、`python3 make_week3.py 明日の日付` で6本を作り直し、目視・quality_check・--check → コミット（note に `実験:D-MMDD 変えたこと`）。**push しない**（翌朝8:00の回で Merge され、10:00 に間に合う）。
   - 実験の結果は「学びログ」タブに1行、3回続けて良かった変更は PATTERNS.md の「採用する型」へ入れて 8:00・12:00 にも広げる（週次PDCAで）。
5. 大きな改善案は日曜に回す（加藤さんの声かけは除く）。報告は2〜3行（今週の進み具合を含める）。夜中に push はしない。

## 作業の終わり（11/9 仕組み化）
- **GitHub は1日2回まで**（11/11 加藤さん）：①朝8:00の回（数字の読み込み＋残りの push）②夜の制作の回（push → PR → Merge をひと続き）。この2回以外では fetch・push・PR・Merge をしない。日次PDCA（この手順）は GitHub に触らず、未 push のコミットは翌朝8:00の回に回すと報告に書く。
- 報告の最後に「GitHub：本日◯回目（2回まで）」と書いて数える。
