## 2. 決まったこと（最新）

### 運用
- Instagram は手足（Claude Code ＋ GitHub Actions）が担当。制作と実装は確認を待たずに進めてよい。公開は PR の Merge（＝承認）のあとだけ。
- Instagram 以外のSNSは保留。
- 加藤さんの修正は毎回シートに記録する。型や日程は直しながら変えていく。

### 投稿の型
- ストーリー：朝8:00に3本、昼12:00に3本（自動）。夜（平日・日20:00、金土21:00）の3本は素材と文を作って渡し、加藤さんが手動でスタンプを付けて出す。
- 3本の中身：①画像 → ②動画 → ③仕掛け。朝・昼の③は、スタンプなしで「プロフィールのリンクから公式LINEへ」（make_week1.py の `kind="line"`）。
- リール：週2本。投稿の2日前21:00までに完成させる。今後の動画は読み上げ音声とBGMを入れる（11/6リールが型）。
- カルーセル：週2本（月曜＝レポート、木曜ごろ＝保存狙い）、各8枚。
- 開催日の朝はフィードで「まだ参加者募集中！」。
- 毎回テーマ案を3つ出してから作る。翌週のストーリーは毎週金曜23:50まで。

### 中身のルール
- 顔は必ず隠す（写真はモザイク、動画は強くぼかす）。体が写っていても、顔を隠せば使ってよい。
- 会場には最寄り駅と徒歩分数。分からない会場は書かない。
- 申込：プロフィールのリンク → 公式LINE → イベントカレンダーから予約 → フォーム → 合言葉をLINEに送る → 参加受付証。
- 当日：受付証を見せる → 参加費1,500円（現金かPayPay）。
- 当日の流れは「（例）」として書き、時間は書かない。残り人数は書かない。
- スケジュールのリールに参加方法の場面は入れない。
- 写真がない日のレポートは、過去写真に「※写真は過去の開催時のものです」と入れる。見ていないこと（人数・雰囲気）は書かない。

## 4. 気づいたこと・リスク（11/6 にリポジトリを見て）

| # | 内容 | 状態・対応 |
|---|---|---|
| 1 | **同じ時刻のストーリーが1本しか出ないおそれ。** ig_queue.py の `already_posted` は、ストーリーについて「予定時刻の5分前以降にストーリーが1本でも出ていれば、出し済み」と判断する。3本同時だと、2本目以降が飛ばされるはず | 加藤さんがテスト予定。だめなら、出した下書きIDで照合するように直すか、予定時刻を1時間ずつずらす |
| 2 | **スタンプは公式APIで付けられない**（投票・質問・リンク） | 夜を手動にして解決 |
| 3 | **リポジトリは公開（public）。** ぼかす前の写真・動画を入れると、顔が誰でも見られる | 実写素材は素材パックに分け、コミットしない。CLAUDE.md に明記 |
| 4 | **素材が作業環境の中にしかない。** 環境が片付けられると消える | setup_studio.sh で確認し、足りなければ素材パックを添付してもらう |
| 5 | **手足が自分から動く「繰り返しの予約」がない**（11/6時点。あったのは1回きりの予約だけ） | 毎週金曜21:30（翌週ストーリー）、投稿2日前21:00（リール・カルーセル）の予約を作る |
| 6 | **Merge が自動実行の時刻より遅いと、その回では出ない。** 自動実行は毎時5分（8:05〜23:05）で、予定時刻から2時間を過ぎると送らない | Merge は予定時刻の前に済ませる。間に合わないときは Actions を手動で実行（dry_run=0） |
| 7 | **動画がたまってリポジトリが重くなる**（週に数十〜100MB） | 投稿済みの media は翌週の下書きPRで消す |
| 8 | **インサイト（数値）を取る仕組みがない。** Meta Business Suite の画面は11月中、一度も読めなかった。日次結果の 11/1〜11/5 は空欄 | 11/6 夜に「Claude Code で読む」と決定。Actions（ig_insights.yml）が毎晩23:50に公式APIで取り、CSVと ChatWork に残す。鍵の見張りもする（設定し直しを防ぐ）。Claude のコネクタは使わない |
| 9 | INSTAGRAM.md の投稿の型が「週7本」で、決定と違っていた | この追加パックで差し替え |
| 10 | GitHub アクセスは普段1日3回・最大4回（11/6 に2回から変更。5回はしない） | 1週間分は1本のPRにまとめる |
